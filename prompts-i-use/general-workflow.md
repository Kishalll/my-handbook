# General Workflow (All Other Uses)

**Trigger**: Any task that is NOT a GitHub issue link — feature requests, code questions, refactoring, debugging, learning, prototyping, etc.

## Core Principles

1. **Don't rush to edits or commits**
2. **Analyze the problem** thoroughly before acting
3. **Understand the project** structure and context first
4. **Make a plan** and present it for approval
5. **Wait for explicit approval** before implementing
6. **Do the fixes** properly and completely
7. **Recheck the work** against the original request
8. **Ask for approval before committing** any changes
9. **For UI/visual changes**: Provide steps to verify after edits

## Clarification Protocol
- If the request is ambiguous or you lack context: **ASK QUESTIONS**
- Do not assume — ask any number of times until clear
- This applies to: requirements, design decisions, tech choices, scope, priority

## Execution
- After approval: implement cleanly, minimal diff
- No unrelated edits, no test/build artifacts unless asked
- Note any discovered issues separately (don't fix silently)
- Verify the result matches the original ask

## Commit & Beyond
- Ask before committing
- For visual changes: give verification steps
